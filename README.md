# 稿间 DraftDock

**稿间**是一款面向 Windows 的本地优先内容发布准备台。它不负责重新生成文章，而是把已经存在于电脑里的 Markdown 与图片，整理成公众号和小红书可以继续使用的交付材料。

> 当前阶段：`0.1.1` Windows MVP。修复安装版启动白屏并增加本地诊断日志。

[下载最新 Windows 安装版或便携版](https://github.com/zznmdhz/DraftDock/releases/latest)

## 为什么做它

AI 可以很快生成一篇文章和一组配图，但真正发布时仍然要反复打开文件夹、切换格式、裁图、复制和寻找图片顺序。DraftDock 把这段“生成之后、发布之前”的工作收进一个桌面工作台。

它坚持四个原则：

1. **文件夹就是文章库**：指定一个根目录，每个一级子文件夹就是一篇文章。
2. **一份 Markdown 是内容源**：公众号与小红书版本都从同一份主稿派生，但允许分别编辑。
3. **原图永不覆盖**：所有裁切、留边和压缩结果都写入独立输出目录，并记录来源与参数。
4. **交付而非代发**：复制、导出和原生文件拖出负责把材料送到平台；发布结果由人确认。

## 已实现

- 选择并持久记忆本地内容根目录
- 自动扫描每个一级子文件夹
- 识别唯一 Markdown 主稿；多份或缺失时给出提示
- 读取 PNG、JPG/JPEG、WebP、GIF、SVG、BMP、TIFF、AVIF
- 自动监听内容目录变化
- 主稿、公众号文章、小红书图文三个独立版本
- Markdown 富文本预览与确定性的小红书纯文本适配
- 完整原图缩略图，不再用强裁切缩略图遮掉内容
- 裁切工作室：原图全览与交付结果并排显示
- 裁切填满与完整留边两种模式
- 微信横封面、方形封面、小红书 3:4、9:16 等用途预设
- 生成独立 PNG 交付文件与可追溯 manifest
- 将真实交付文件从应用拖到其他 Windows 应用
- 复制 Markdown、公众号 HTML 富文本或小红书纯文本
- 导出带所选图片的 DOCX
- 本地保存平台稿件，不需要账号、服务器或云端素材库

## 内容目录约定

```text
内容根目录/
├─ 2026-09-19-一篇文章/
│  ├─ article.md              # 建议且仅有一份 Markdown
│  ├─ 01-cover.png
│  ├─ 02-detail.jpg
│  └─ diagram.svg
└─ 另一篇文章/
   ├─ main.md
   └─ images...
```

DraftDock 首次保存或生成交付材料后，会在文章文件夹内创建：

```text
.draftdock/
├─ state.json                 # 各平台独立稿件
├─ manifest.json              # 原图到交付图的追溯记录
└─ outputs/
   ├─ wechat/
   └─ xiaohongshu/
```

`.draftdock` 中的内容不会被再次当作原素材扫描。完整约定见 [目录规范](docs/DIRECTORY-SPEC.md)。

## Windows 开发与构建

需要 Node.js 22+ 与 pnpm。

```bash
git clone https://github.com/zznmdhz/DraftDock.git
cd DraftDock
pnpm install
pnpm dev
```

类型检查、测试与正式构建：

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm dist:win
```

Windows 安装包和便携版会生成到 `release/`。

## 使用流程

1. 选择存放文章文件夹的根目录。
2. 从左栏选择一篇文章。
3. 切换公众号或小红书版本，检查并编辑派生正文。
4. 在中栏查看完整图片，进入“适配并生成”。
5. 在裁切窗口左侧确认完整原图，右侧调整交付范围或使用完整留边。
6. 生成新文件后，按住“拖出交付图”拖到平台上传区，或打开文件位置。
7. 复制正文或导出 DOCX，在平台端完成最终检查。

## 数据与安全

- 所有文章、图片、平台稿件和派生图均保存在本地。
- Renderer 不具有 Node.js 权限；文件操作统一经过受控 IPC。
- 应用只允许访问当前选定内容根目录下的路径。
- Markdown 预览和复制前会清理不安全 HTML。
- 应用不保存公众号、小红书登录状态，也不接管浏览器 Cookie。

## 日志与白屏排查

页面右下角“诊断日志”或按 Alt → 帮助 → 打开日志文件夹，即可找到 `draftdock.log`。默认位于 `%APPDATA%/draftdock/logs/`（以实际打开位置为准）。

日志记录启动版本、会话标识、页面加载、预加载异常、React 错误、未处理异常、目录扫描和 IPC 操作耗时/失败。正文、剪贴板内容和图片数据不会作为操作参数写入；错误堆栈可能包含本地路径，分享前请检查。日志仅在本机保存，不自动上传。

单文件达到 5 MB 后轮转，保留 5 个历史文件。页面启动失败时显示诊断提示；页面脚本未加载时也有静态提示，可通过帮助菜单打开日志或重新加载。

维护者可在打包后运行 `node scripts/smoke-packaged.mjs`，验证实际页面渲染、桌面接口、IPC 和日志，并保存启动截图。该检查使用独立临时配置目录，不影响用户文章库。

## 当前边界说明

- 不自动登录或发布到平台。
- 不把图片自动插入目标平台正文中的准确位置。
- 不承诺网上流传的平台字数、张数和尺寸限制；预设是可验证的工作默认值。
- GIF 当前按首帧生成静态交付图。
- SVG 可以读取并栅格化为 PNG 交付文件，原 SVG 保持不变。
