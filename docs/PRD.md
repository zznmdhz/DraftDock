# DraftDock Windows MVP 产品说明

## 产品定位

DraftDock 是一个本地内容发布准备台。它连接“AI 已经生成好的文章素材”和“平台后台真正能接收的发布材料”，不承担选题、写作、账号运营或无人值守发布。

## 目标用户

- 使用 ChatGPT、Claude、Gemini 或其他 AI 生成文章与配图的个人创作者。
- 同时运营公众号与小红书，需要重复处理格式和图片比例的人。
- 希望素材继续由普通文件夹管理，不愿把全部内容上传到 SaaS 的用户。

## 核心任务

用户选择一个内容根目录后，能完成：

```text
扫描文章文件夹
→ 读取唯一 Markdown 与全部原图
→ 形成平台独立正文
→ 从完整原图生成非破坏性交付图
→ 复制文字 / 导出 DOCX / 拖出真实图片文件
→ 人工检查并发布
```

## MVP 验收标准

### 目录与文章

- 一个一级子目录对应一篇文章。
- 找到一份 Markdown 时自动加载；找不到或超过一份时明确提示。
- 新增、删除或修改文件后，文章库能自动刷新。

### 图片

- 原图卡片必须完整显示整张图，而不是默认裁成缩略图框。
- 至少支持 PNG、JPG/JPEG、WebP、GIF、SVG、BMP、TIFF、AVIF 的发现和读取。
- 裁切界面必须同时显示“完整原图”和“交付结果”。
- 每次生成都创建新文件；不得修改、移动、改名或覆盖原图。
- 输出记录必须包括原图路径、平台、用途预设、目标尺寸、模式、裁切参数和生成时间。
- 已生成文件可从 Electron 原生拖到其他 Windows 应用。

### 正文

- 只从选中的 Markdown 主稿派生平台版本。
- 公众号版本保留 Markdown 结构并可复制为清理后的 HTML 富文本。
- 小红书版本使用确定性规则去除 Markdown 标记，用户可继续编辑。
- 平台稿件自动保存，但不会回写或覆盖 Markdown 主稿。
- 能导出包含正文和选中图片的 DOCX。

## 非目标

- AI 自动改写、自动总结或自动生成平台爆款文案。
- 自动登录、保存 Cookie、多账号管理或无人值守发布。
- 热点采集、选题库、运营大屏、复杂审批。
- 对平台未公开或不断变化的规则作永久硬编码承诺。

## 数据原则

- 主稿与原图是用户源文件，应用默认只读。
- `.draftdock/state.json` 是平台工作稿。
- `.draftdock/manifest.json` 是派生记录。
- `.draftdock/outputs/` 是可删除并重新生成的交付物。
